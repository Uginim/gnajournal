# 블로그 콘텐츠 후보 (gist 기반)

개인 학습 gist 중 블로그 글로 정제 가능한 주제 목록. **사내 식별자, 티켓번호, 테이블명, PR번호는 모두 제거**하고 일반화한 뒤 게시한다. (게시 콘텐츠 과장, 거짓 금지 규칙, 타사/사내 IP 보호 규칙 적용)

## 상태 범례
- ✅ 게시됨 / 🚧 초안 / 🔲 미착수

---

## DB, SQL 계열 (블로그 주축)

| 상태 | 주제 | 핵심 내용 | 분량감 |
|---|---|---|---|
| ✅ | 데이터베이스 정규화 시리즈 | 1NF~BCNF, 이상현상, 함수적 종속 | 시리즈(1~6편 게시, 7편 draft) |
| ✅ | IN vs EXISTS | semijoin, 옵티마이저, 버전 의존성 | 단발(초안 완료, 게시 대기) |
| 🔲 | 트랜잭션과 락 | InnoDB 락 종류 / MVCC / Spring @Transactional propagation | 시리즈감(3편 분할 가능) |

## JPA, Hibernate 계열

| 상태 | 주제 | 핵심 내용 | 분량감 |
|---|---|---|---|
| ✅ | JPA N+1 문제 비교 | fetch join / EntityGraph / batch size | 단발(게시됨) |
| ✅ | 테스트 OOM: 컨텍스트 캐시 | Spring TestContext 캐시 키 + H2 DB 이름 | 단발(게시됨) |
| 🔲 | **orphanRemoval + 유니크키 충돌** | clear+add 치환 시 INSERT→DELETE 순서로 UK 위반. ActionQueue flush 순서 | 단발(원인분석형, 임팩트 큼) |
| 🔲 | 엔티티 리스너에서 DI가 안 되는 이유 | `@EntityListeners` 콜백은 Hibernate가 생성 → 스프링 빈 주입 불가, 우회법 | 단발(원인분석형) |
| 🔲 | pooled-lo ID 채번 전략 | Hibernate가 시퀀스를 미리 당겨오는 이유, allocationSize 트레이드오프 | 단발 |
| 🔲 | Hibernate Envers | 감사 로그 내부동작, 운영 한계 | 단발(니치, 경쟁 적음) |

## Claude Code 계열

| 상태 | 주제 | 핵심 내용 | 분량감 |
|---|---|---|---|
| ✅ | 프롬프트 캐싱 구조 | prefix 일치, 무효화 조건, 비용 구조, 실측 | 단발(게시됨) |
| ✅ | 토큰 절감 도구 | 공식 기능과 서드파티 도구, 캐시 위험 등급 | 단발(게시됨) |
| 🔲 | 컨텍스트가 많으면 정확도가 떨어지나 | 캐싱 글 부록에서 분리(2026-07-16). 캐싱과 무관한 품질 문제. 컨텍스트가 커질수록 필요한 정보가 묻히고, 앞과 끝의 정보가 가운데보다 잘 활용되는 경향. 근거: [Lost in the Middle (Liu et al., 2023)](https://arxiv.org/abs/2307.03172). 확장 방향: 실측(같은 질문을 컨텍스트 크기별로), 컨텍스트 윈도우 1M 시대에도 유효한가, /clear와 서브에이전트가 품질에 주는 효과 | 단발(부록 3문단이 시드) |

## 우선순위 추천
1. **orphanRemoval + 유니크키 충돌**: 증상→원인→근거 전개가 명확, 기존 원인분석형 글과 결 동일
2. **트랜잭션과 락**: 시리즈로 확장 가능, 검색 수요 큼
3. **엔티티 리스너 DI 함정**: 짧고 실무 공감대 큼
